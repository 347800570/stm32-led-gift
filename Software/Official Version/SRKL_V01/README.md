# SRKL V01：74颗灯珠空间布局移植

## 工程入口

- Keil 工程：`MDK-ARM/MPLT.uvprojx`，目标名 `MPLT`。
- 固件：`MDK-ARM/MPLT/SRKL.hex`；调试文件：`MDK-ARM/MPLT/SRKL.axf`。目录中旧的MPLT.hex不是本次移植产物。
- STM32F042G6U6TR，系统时钟 HSI48，48 MHz。
- PB0 / TIM3_CH3 / DMA1_Channel2 控制一条 74 颗 WS2812B 灯带。
- PA3 / EXTI 双边沿接收 NEC 红外，用户码字节为 `00 FF`。
- TIM14 自由运行，1 MHz，每 65.536 ms 回绕，不要在其他模块清零。
- USART1：PB6 TX、PB7 RX，115200、8N1，只输出日志。
- DS18B20：PA2 开漏、外部上拉、独立 VDD 供电；仅支持总线上一颗传感器，不使用寄生供电。
- 麦克风：PA0/ADC_IN0，TIM1 TRGO 8 kHz触发，DMA1_Channel1循环接收。
- 第二路灯带、PA1 实体按键保留基础配置，不启动业务。

## 操作规则

上电开灯，模式 3，亮度 15%，速度第 3 档，声音灵敏度第 3 档。

| 按键 | NEC 键码 | 功能 |
| --- | --- | --- |
| POWER | 0x45 | 开关灯，重新打开时恢复模式和参数 |
| 1 | 0x0C | 整条七色循环，默认保持 1 秒、渐变 1 秒 |
| 2 | 0x18 | 暖橙呼吸，默认一个周期 3 秒 |
| 3 | 0x5E | 流动彩虹，沿 1→74 方向移动 |
| 4 | 0x08 | 蓝白流星，沿 1→74 方向移动 |
| 5 | 0x1C | 暖白星光，随机位置淡入淡出 |
| 6 | 0x5A | 整板空间火焰，从木板底部向上升腾 |
| 7 | 0x42 | 环境温度颜色，18°C蓝、25°C绿、32°C红 |
| 8 | 0x52 | 空间音量柱，按实际高度从下往上点亮，绿→黄→红 |
| 9 | 0x4A | 低频鼓点触发整条闪光脉冲，颜色缓慢循环 |
| + | 0x40 | 增亮 3 个百分点，上限 30% |
| - | 0x19 | 减亮 3 个百分点，下限 3% |
| LEFT | 0x07 | 1～7号减速；8/9号降低声音灵敏度 |
| RIGHT | 0x09 | 1～7号加速；8/9号提高声音灵敏度 |

速度为 0.5、0.75、1、1.5、2 倍。数字键切换后重置动画。
POWER关闭时冻结动画，重新打开后继续；模式、亮度、速度、灵敏度均保留。
采样始终运行，重新打开声控模式时显示当前声音强弱。静音熄灭不等于POWER关机，仍可用数字键切模式。
关灯时所有非 POWER 按键均不改变状态，数字键也不能唤醒。
仅调整键支持长按：至少等待 350 ms，随后相邻调整至少间隔 160 ms；
实际间隔还取决于遥控器重复帧发送周期。POWER、模式键忽略 NEC 重复码。
重复帧距离上一个有效帧超过 180 ms 时不执行。
未分配键只输出提示。断电后全部恢复默认，不写 Flash。
温度模式的颜色只由温度决定，速度键仍改变全局速度设置，但不改变温度采样周期。

## V03 声控功能

### 数据流程

ADC硬件校准 → 启动128点循环DMA → 启动TIM1 → 每64点处理一次 → 去直流。
随后分两路：8号计算音量包络；9号提取低频能量并检测鼓点，触发独立灯光脉冲。

TIM1时钟48 MHz，PSC=47、ARR=124、TRGO=Update，采样周期125 us。
ADC为12位右对齐，DMA两端Half Word；独立缓冲128×2=256 B，每半缓冲64点对应8 ms。
ADC DMA回调只处理64点整数数据，不打印、不等待；红外中断优先级0，ADC DMA优先级1。
从已完成且DMA当前没有写入的半缓冲读取；处理前后核对DMA位置，发现过期数据就丢弃并恢复采样。

直流偏置由低通跟踪，时间常数约32 ms；初值取首个样本，以避免1.65V偏置造成虚假音量。
8号使用去直流后的平均绝对幅度，固定噪声门为 `Core/Inc/audio.h` 的 `AUDIO_NOISE_GATE=12`，不做上电背景噪声学习。
8号亮度每8 ms更新，上升向目标靠近一半，下降向目标靠近十六分之一，最终精确回到0。
9号采用低频能量突增检测，无FFT；不将8号包络或原始音量直接映射为亮度。

### 8号：空间音量柱

声音越大，点亮高度越高。四个字共同使用原来的y坐标，低处绿色、中间黄色、高处红色。
每个高度层独立使用亮灭滞回：超过原点亮阈值才点亮，已点亮后要降到更低的熄灭阈值才熄灭。
默认熄灭阈值比点亮阈值低一层音量跨度的25%；例如y=6层LEVEL达到128点亮，降到122及以下才熄灭。
123～127之间保持之前状态，同高度灯珠同步。临界层点亮后保留至少64/255的效果亮度，再统一乘全局亮度，避免RGB在零附近反复跳动。
亮度变化采用约80 ms满幅过渡；静音/采样故障的LEVEL=0会立即清空滞回状态并全黑，重新进入模式也重置状态。
参数位于 `Core/Inc/effects.h`：`VOLUME_HYSTERESIS_PERCENT`（默认25，允许1～99）、
`VOLUME_HOLD_BRIGHTNESS`（默认64）、`VOLUME_FADE_MS`（默认80）。若实物仍有边界闪烁，可适当增大滞回百分比。
整体仍受3%～30%的全局亮度设置限制。

### 9号：鼓点律动

全部74颗灯珠在检测到低频鼓点后立即达到固定效果峰值，再用150 ms线性渐灭。实际峰值仍受全局亮度限制。
每次触发后150 ms内不重复触发，两个鼓点之间的小幅音量波动不改变已触发的脉冲。
颜色保持12秒缓慢循环，LEFT/RIGHT调整鼓点触发难度，不改变色彩周期或单次脉冲峰值。

滤波器在8 kHz采样下使用一阶约40 Hz高通，串联两个一阶约400 Hz低通，同时保留更多中低频鼓声。
低通系数由37改为69；400 Hz指每个一阶环节，串联后的整体截止频率并非400 Hz，也不是理想带通边界。
能量先做短时平滑，再同时检查绝对门槛、相对近期背景能量的倍数以及能量明显上升。
触发后还要求能量回落再重新允许触发。背景以约256 ms时间尺度持续跟踪，采样启动前128 ms只建立滤波与背景状态。
切换模式清除尚未结束的闪光脉冲，检测器继续跟踪背景。采样故障立即全黑；恢复采样会重新建立背景状态。

参数在 `Core/Inc/beat.h`：`BEAT_REFRACTORY_MS`防重复间隔、`BEAT_PULSE_MS`渐灭时长，默认均为150。
`BEAT_HP_COEFF_Q8`、`BEAT_LP_COEFF_Q8`对应滤波系数，随采样率变化需重新设计。
旧的 `AUDIO_PULSE_RELEASE_DIVISOR` 已移除。
这是一种轻量能量突增检测，真实音乐仍需调试；拍桌、碰撞等低频冲击也可能触发，低频不明显的鼓声可能漏检。

### 灵敏度与噪声门

8/9号共用5档灵敏度，切模式保留、上电默认第3档。1～7号动画速度独立保存。
8号每档满量程交流幅度（已扣除噪声门）为320、200、128、80、48个ADC码值；数值越小越灵敏。
可在 `Core/Src/audio.c` 的 `full_scales` 中修改，8号噪声门在 `audio.h` 中修改。
9号参数在 `Core/Src/beat.c`：绝对门槛 `floors` 为144、100、64、36、16，背景倍数 `ratios` 为3.00、2.50、2.00、1.50、1.00。
保留移植时MPLT_V03及目标工程中现有的调试参数：第5档门槛为背景加16，未回退到此前说明中的1.60倍；重新允许触发条件和150 ms时序不变。
能量单位为滤波后ADC码值平方/16；判断门槛为背景乘对应倍数再加绝对门槛，不能将这些数值与AMP直接比较。

建议先用默认参数测试，安静时记录AMP范围，再对照正常说话/音乐时的AMP：

- 8号安静时仍频繁亮灯：将噪声门略调高到安静AMP之上。
- 正常声音很少点亮：按RIGHT提高灵敏度，再考虑调整对应幅度范围。
- 经常满格：按LEFT降低灵敏度。
- CLIP持续较高：检查模拟输入是否接近0V/3.3V，可能需要降低模拟放大倍数；软件灵敏度不会修复模拟削顶。
- 9号误触发时按LEFT降低灵敏度；鼓点漏检时按RIGHT提高，结合LOW、BG及BEATS观察触发效果。

### 日志与故障

串口每秒输出例如 `AUDIO OK AMP=60 LEVEL=96 LEVEL9=80 LOW=140 BG=30 BEATS=4 BIAS=2048 CLIP=0 ERR=0 BLOCKS=125`。

| 字段 | 含义 |
| --- | --- |
| WAITING/OK/FAULT | 等待首块/采样正常/采样故障 |
| AMP | 最新64点去直流后的平均绝对幅度，单位ADC码值，未经噪声门处理 |
| LEVEL | 8号使用的0～255音量包络，故障时0 |
| LEVEL9 | 9号鼓点闪光脉冲的当前亮度，0～255，故障时0 |
| LOW / BG | 当前低频能量 / 背景能量估计 |
| BEATS | 本次采样启动以来检测到的鼓点次数；日志每秒一次，短脉冲可能看不到LEVEL9峰值，可看计数是否增长 |
| BIAS | 直流偏置估计，正常约2048，取决于实际模拟电路 |
| CLIP | 最新一块中小于等于8或大于等于4087的采样数量，范围0～64 |
| ERR | 采样失败/恢复错误累计次数 |
| BLOCKS | 已处理的有效半缓冲块数，正常每秒约增加125 |

超过100 ms没有新数据、ADC溢出、DMA错误或过期半缓冲均使声控输出归零，每秒尝试重新校准并启动采样。
红外和其他灯效继续工作；安静输入本身不会报错。ADC正常采样并不等于麦克风本体正常，持续直流/削顶需结合BIAS、CLIP检查硬件。

#### 鼓点窗口诊断

新增 `BEAT WIN VALID=1 PEAK=100 TH=70 BG=3 SENS=3 HIT=1 BELOW=110 RISE=8 ARM=5 LOCK=1`。
与温度/音频日志错开500 ms输出，正常每秒一次；第一次窗口约1.5秒，采样重启会清空窗口。
峰值与门槛/背景在同一采样块记录，再在主循环短暂关中断取出并清空统计；中断内不打印。

- `VALID`：是否包含预热之后的有效块；为0时本行没有可分析的数据。
- `PEAK`：本窗口最大的平滑低频能量；`TH`、`BG`、`SENS`为出现该峰值时的门槛、背景及灵敏度。
- `HIT`：本窗口触发次数；`BEATS`仍为采样启动以来累计次数。
- `BELOW`：能量没有超过门槛的块数。
- `RISE`：已超过门槛，但相比上一块上升不足的块数。
- `ARM`：已满足门槛及上升条件，但上次触发后能量尚未充分回落的块数。
- `LOCK`：其他条件满足，但距上次触发还不足150 ms的块数。

每块只归入一个结果，按BELOW、RISE、ARM、LOCK的顺序记录首个失败条件，否则计入HIT。
各计数之和正常约125/秒（不含启动预热块）；每项最大65535，避免长时间不取日志时回绕。
这些是采样块统计，不是漏掉的鼓点数量。PEAK对应的块也不一定就是成功触发的块。
调试先保持同一音源、音量和灵敏度，对照PEAK与TH；本次没有降低门槛或改变150 ms时序，8号算法不变。

## 空间火焰与温度模式

### 6号：空间火焰

使用用户确认的 `灯带位置.txt`，与 `Core/Src/led_layout.c` 中的 74 个坐标一一对应。
坐标原点在木板左下方，x=0～32、y=0～11。按新TXT的制表符列和行保留空隙；忽略顶部空行，底部为y=0。

33×12 热量网格占396 B RAM。底部随机补充热量，向上扩散、逐层冷却；四个字共享同一片热场，
空隙处也计算热量，并非每个字各自燃烧。热量映射为黑、红、橙黄、淡黄白。
中档每40 ms更新一步，LEFT/RIGHT调整火焰速度；1～5号仍按灯珠串联顺序或随机位置显示。

### 7号：环境冷暖

- 18°C及以下为蓝色；25°C为绿色；32°C及以上为红色，区间线性插值。
- 约每秒发起一次转换。首次有效值直接采用，以后每个有效样本向新温度靠近四分之一。
- 转换等待760 ms期间立即返回主循环，不使用 `HAL_Delay(750)`。
- 暂存器分9次任务调用读取，每次读取一字节；校验CRC、配置保留位和-55～125°C范围。
- 不写配置寄存器或EEPROM；兼容9～12位分辨率，屏蔽低分辨率下的未定义低位。
- 上电未收到有效数据时暂不点亮温度颜色。短暂失败保持上次颜色；距离上次有效样本满5秒，显示低亮紫色。
- 有效数据恢复后自动恢复温度颜色。关灯和其他模式下也持续测温，所以切换到7号无需重新等待。
- 只表示环境冷暖，不承担过温保护。

每秒串口输出例如 `TEMP OK LAST=25.00C SAMPLES=12`。
`LAST` 是最新成功读取的温度，不是经过平滑的显示值；读取失败时可能保留旧值。
状态包括 `WAITING`、`OK`、`NO_DEVICE`、`CRC_ERROR`、`BAD_DATA`、`NOT_READY`；超时另附 `FAULT`。

### 与红外共存

TIM14由 `IR_Init()` 启动，温度延时只计算时间差、不清零计数器。
复位低电平480 us期间保持中断开放；仅存在脉冲采样和读写位的关键窗口短暂屏蔽中断。
最长计划延时窗口为70 us，另有少量指令开销；不再将整个复位过程近1 ms都关中断。
各窗口恢复调用前的PRIMASK；实际板上仍需验证温度采样期间连续遥控是否可靠。

## 代码阅读顺序

1. `Core/Src/main.c`：CubeMX 初始化后调用 `App_Init()`，主循环调用 `App_Task()`。
2. `Core/Src/app.c`：先取红外事件并更新状态，再按约 20 ms 周期生成和发送画面。
3. `Core/Src/ir.c`：边沿间隔驱动 NEC 状态机，完整校验后放入事件队列；中断里不打印日志。
4. `Core/Src/effects.c`：根据模式、速度、经过时间，生成不含全局亮度缩放的 RGB 数组。
5. `Core/Src/led.c`：限制亮度，编码为 GRB、高位先发，DMA 异步输出。
6. `Core/Src/debug_log.c`：主循环检查 TXE，非阻塞发送日志。不要同时用其他 UART 发送函数操作 USART1。
7. `Core/Src/temperature.c`：发起转换、等待、分段读暂存器、校验及平滑。
8. `Core/Src/led_layout.c`：74颗灯珠的只读空间坐标，存放在Flash。
9. `Core/Src/audio.c`：ADC启动/恢复、DMA半缓冲处理、声音幅度和平滑包络。
10. `Core/Src/beat.c`：低频滤波、能量突增检测、防重复触发和独立灯光脉冲。

灯带发送期间不修改 DMA 缓冲。发送完成回调停止 DMA；异常或超过 20 ms 未完成时停止并重试。
关灯请求保留到黑帧成功提交，即使上一帧正在发送也不会丢失。
DMA 缓冲为 2034 B：2 个前导零 + 74×24 数据位 + 256 个复位零。
末尾低电平约 320 us，帧间另留至少一个 HAL tick。
效果和日志没有使用长时间阻塞延时、动态内存或浮点运算。

## CubeMX 与工程维护

自定义代码位于独立文件，main.c 的调用位于 USER CODE 区域。
Keil 的 `SRKL Application` 分组包含 app、led、effects、ir、debug_log、temperature、led_layout、audio、beat 九个源文件。
若再次生成 CubeMX 工程，请检查该分组仍在，否则手动重新加入这些文件。
灯珠数量集中在 `Core/Inc/led.h` 的 `LED_COUNT`；空间映射固定为74颗，修改数量必须同步修改坐标并检查RAM和发送时间。
V03将CubeMX HeapSize及启动文件Heap_Size同步改为0，保留StackSize=0x400。后续不要直接引入malloc/calloc/realloc或依赖堆的库。
星光和火焰在union中共用396 B工作区，切模式清零、星光按需初始化；麦克风缓冲始终独立，不能与效果共用。
30% 是软件亮度缩放上限，不是闭环电流限制。

## 上板验证顺序

1. 打开上述 Keil 工程编译并烧录。若使用 USB DFU，HEX 自带地址；下载后将 BOOT0 恢复正常启动并复位。
2. 串口设115200、8N1，应看到 `SRKL V01 READY`，模式3、15%亮度、SPEED=3、SENS=3；灯带显示流动彩虹。
3. 逐个按 1～5，核对五种效果；按 +、-、LEFT、RIGHT，核对方向及上限下限。
4. 长按 POWER，确认只开关一次；长按数字键，确认动画不会反复重置。
5. 长按 +、-、LEFT、RIGHT，确认重复调节及限幅。
6. 关灯后按1～9和调节键，应保持熄灭；POWER再开应恢复之前状态。
7. 开灯时按MENU、0等未分配键，应显示 `UNASSIGNED IN SRKL V01`，画面不切换。
8. 断电重启，恢复模式 3、15% 亮度、中档速度。
9. 连续切换和长按测试，观察是否出现 `LED DMA ERROR` 或大量 `IR INVALID/OVERFLOW`。
10. 按6号，确认四个字共同从木板底部向上燃烧；LEFT/RIGHT应改变火焰速度。
11. 按7号，查看串口温度与颜色对应；用手握住探头缓慢加温，颜色应逐渐向红色方向变化。
12. 断开传感器信号后短时保留颜色，最后一次成功读取满5秒后变低亮紫色；重新接回后自动恢复。
13. 测温过程中持续按键和长按调节，确认不会由于测温丢失大量红外指令。
14. 按8号，说话或播放音乐，确认从下往上显示音量，边界层渐亮；安静后逐渐全黑。
15. 按9号播放底鼓清晰的音乐，确认每次鼓点触发全条短脉冲、颜色缓慢变化；鼓点间隙不应跟随噪声持续抖动。
16. 在8/9号中用LEFT/RIGHT调整SENS，确认范围1～5且两个模式共用；切回3号后LEFT/RIGHT仍改变SPEED。
17. 连续运行并切换5、6、7、8、9号，观察BLOCKS持续增加、ERR不增长，同时确认温度和红外正常。
18. 8号模式下保持临界大小的声音，观察同高度灯珠不再因小幅音量波动反复亮灭；逐渐降低声音，确认降得更低才熄灭。效果仍需实物验证。

若串口有正常按键日志但灯带不亮，优先检查数据接到 PB0 对应的 LED1_DATA、灯带 DIN 方向、5V 与共地。

## SRKL移植说明

硬件接线和遥控器沿用MPLT_V03，PB0驱动74颗；9种模式、当前鼓点第5档1.00倍门槛、上电默认第3档均保留。
火焰每层冷却按7/11缩放，补偿高度从8行增加到12行；整板仍共享一片火焰。
Keil入口保留 `MDK-ARM/MPLT.uvprojx` 和MPLT构建目标以兼容现有RTE配置，输出为 `MDK-ARM/MPLT/SRKL.hex`、`SRKL.axf`。
CubeMX文件为 `SRKL.ioc`，重新生成后可能产生新的SRKL Keil工程，需要核对自定义源文件分组。
